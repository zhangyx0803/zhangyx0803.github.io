反演地表温度时，最容易写反的三行代码

2026.11.08遥感 · Landsat · ArcGIS

用 Landsat 8/9 做 LST 反演，流程本身不复杂：定标 → 云掩膜 → DN 转摄氏度。 真正花时间的是三处写反了也不报错的地方。

一、Con 的语义

ArcGIS 的 Con(condition, value) 是「条件为真时取该值」。要保留晴空像元，条件必须写成「坏值等于 0」：

lst = Con(bad == 0, lst_raw)   # 对：晴空保留
# lst = Con(IsNull(valid), lst_raw)  # 错：语义正好反过来

写成 IsNull(valid) 时，留下的是云、丢掉的是晴空。实测有效像元从 43.9% 掉到 8.4%， LST 最大值飙到 92 ℃，NDVI 出现 -231——量级完全不对，但代码不报错。

二、归一化指数的除零

(NIR - Red) / (NIR + Red) 在分母接近 0 时会炸。未做保护时见过 NDVI = -2319、NDWI = +12105。

denom = nir + red
ndvi = Con(denom > 0, (nir - red) / denom, 0)

三、越界值：夹，不要删

归一化指数理论上落在 [-1, 1]，实际会因为大气校正残差越界。两种处理差别很大：

  • 删掉：像元数变少，后续面积统计偏小；
  • 夹回边界：像元保留，值被截断到 [-1, 1]。

对「按阈值筛冷源」这类分析，删像元等于制造空洞，后续斑块统计会失真。所以用 Con 夹：

ndvi = Con(ndvi > 1, 1, Con(ndvi < -1, -1, ndvi))

怎么尽早发现

三个检查，跑完立刻做：

  1. 有效像元占比（正常情况下 30%–90%，掉到个位数就是掩膜写反了）；
  2. LST 的最小 / 最大值（夏季上海大约 20–55 ℃，出现 90 ℃ 说明换算错）；
  3. NDVI 的极值（越界到 -2000 说明没防除零）。

这三条不解决，后面 MSPA 和阻力面怎么调都是错的。
